# Module 1 차량·승객 운행

Module 1은 호출 시나리오를 읽고 지정된 택시가 승객을 픽업·운송하도록 한다.
이번 구현 범위는 택시와 승객이며, 재배치 기능은 포함하지 않는다.
예측 모델과 Module 4의 정식 배차 정책은 구현하지 않는다.
사용자가 선택한 운행 확인용 ‘호출 순서대로 가까운 빈 택시 연결’을 개발 시연에만 사용한다.
현재 범위는 승객의 **출발지 대기 → 픽업 → 택시 탑승 이동 → 하차**이다.
보행, 충돌 회피, 교통 신호와 승하차 소요 시간은 모델링하지 않는다.

좌표·구역·시간·경로·상태 전이·명령·측정의 의미는
[공용 계약 6절](contracts/common_contracts.md#6-module-1-운행-경계--임시-01)이 단일 원본이다.
다른 모듈 통합 전 재검토할 임시 `0.1` 계약이며, 예전 순환 이동 시제품의
`route` 설정은 더 이상 지원하지 않는다.

## 실행

Python 3.13 환경 설정은 [개발 시작 가이드](development_start_guide.md)를 따른다.
저장소 루트에서 다음 명령을 실행한다.

```bash
python -m pip install -e ".[dev,simulation]"
python -m module1_simulation
```

기본 실행은 **시작 시각 0에 손님 한 명, 이후 10초마다 한 명씩** 계속 등장시킨다.
호출이 생기는 순간 출발·도착을 16개 교차로에서 서로 다르게 무작위로 뽑는다.
호출은 `call-1`, `call-2`, `call-3`처럼 계속 증가하며 묶음이나 회차는 없다.
이전 승객이 운행을 마쳤는지와 무관하게 다음 호출이 발생한다.

- 도시·속도·초기 택시 위치·tick: `configs/module1_demo.toml`
- 호출 간격·난수 시드: `configs/module1_calls.toml`의 `interval_seconds`, `seed`
- 호출 간격은 시뮬레이션 시간 기준이며 tick의 양의 정수 배수여야 한다.
- 시드는 호출 위치만 제어하며 전역 난수에 영향을 주지 않는다.
- R 초기화 시 시계·택시·승객·기록·호출 번호·난수 순서를 초기화한다.
- 개발용 입력이며 현실 수요 모델이나 학습 데이터 생성기가 아니다.

운행 확인용 연결은 다음과 같다.

- 호출을 발생 시각·호출 ID 순서로 처리한다.
- 현재 빈 택시 중 출발지까지 도로 이동 거리가 가장 짧은 택시를 선택한다.
  거리 동률이면 택시 ID 순으로 선택한다.
- 모두 운행 중이면 승객은 기다린다. 매 tick 운행 완료 후 다시 확인한다.
- Module 4의 정식 정책을 연결할 때 이 개발용 자동 연결기를 대체한다.

```bash
python -m module1_simulation --call-interval 3
python -m module1_simulation --seed 7
python -m module1_simulation --manual
python -m module1_simulation --headless --steps 1200 --events
python -m pytest
```

헤드리스 모드는 화면·Panda3D 없이도 동작하며 관측·측정과 선택적 이벤트 로그를
JSON 표준 출력으로 반환한다. 파일이나 외부 서비스로 전송하지 않는다.
`--config`로 도시 설정, `--calls-config`로 개발용 호출 설정을 바꾼다.
`--call-interval`과 `--seed`는 설정 파일의 값을 덮어쓴다.

유한한 외부 시나리오를 확인하려면 `--scenario <JSON 경로>`를 명시한다.
이때는 파일의 호출만 적재하며 추가 호출을 발생시키거나 위치를 바꾸지 않는다.
회귀 테스트 입력은 `tests/fixtures/`에 있으며 기본 실행에서는 읽지 않는다.
기존 `--repeat-seconds`, `--once`, `--fixed-locations` 옵션은 제거했다.
이전 고정 배차 시연의 `--commands` 옵션과 명령 예약 큐도 제거했다.
잘못된 명령은 헤드리스 실행을 오류로 종료하거나 화면에 이유를 표시하며 멈춘다.
직접 호출하는 `dispatch()`와 수동 화면 조작은 운행 중인 택시에 대한 명령을 거부한다.

## 화면과 조작

흰 배경을 유지하며 택시 상태는 `Waiting`, `Picking up`, `With passenger`로
표시한다. 지붕 표시는 대기 노랑·픽업 파랑·탑승 초록이다.
출발지의 작은 사람 모형은 기다리는 승객이다. 탑승 중에는 사람 모형을 숨기고
택시와 탑승 인원 표시로 나타낸다. 내부 승객 좌표는 택시를 따라 이동한다.
하차한 승객은 목적지에서 3초간 표시한 뒤 화면 객체를 제거하며, 완료 기록은 보존한다.
승객 모형의 도로 옆 표시 위치는 가독성을 위한 화면용 오프셋이다.

오른쪽에는 호출 대기 인원·탑승 인원·하차 완료 건수와 평균 픽업 대기 시간이 표시된다.
평균은 픽업한 승객만 포함하므로 대기 인원과 함께 읽어야 한다.

| 키 | 동작 |
|---|---|
| Space | 시뮬레이션 일시정지·재개 |
| R | 호출·차량·측정·이벤트·시연 명령을 초기화 |
| 1 / 2 / 3 | 0.5 / 1 / 2배속 |
| 방향키 / 마우스 휠 | 카메라 조절 / 확대·축소 |
| D | 차량 좌표 표시·숨김 |
| Esc | 종료 |

`--manual` 실행에서는 자동 시연 명령을 읽지 않는다. 호출은 시각에 따라 발생하지만
택시는 사용자가 명령할 때만 움직인다. Space로 멈춘 상태에서도 선택·명령할 수 있다.

| 키 | 수동 모드 동작 |
|---|---|
| T | 명령할 택시 선택 |
| C | 발생한 배차 대기 호출 중 선택 |
| Enter | 선택한 택시에 선택한 호출 배차 |

잘못된 명령은 화면에 이유를 표시한다. 택시·승객 연결은 `idle` 택시만 허용한다.

## 다른 모듈 연결

공개 facade를 통해 명령하고 관측한다. 내부 파일·미래 시나리오를 정책에서 참조하지 않는다.

```python
from module1_simulation import Simulation, load_calls, load_config

sim = Simulation(load_config("configs/module1_demo.toml"),
                 load_calls("tests/fixtures/module1_calls.json"))
current = sim.observe()  # 발생한 호출만 노출
sim.dispatch("taxi-1", "call-1")
sim.advance(240)
print(sim.metrics())
print(sim.events())
```

Module 4는 각 tick 이후 `observe()`의 현재 정보로 판단하고 명령을 전달한다.
연결 시 `DemoRunner`의 개발용 자동 연결기를 끄고 외부 정책으로 대체한다.
화면 재생 속도에 관계없이 같은 tick에 같은 명령을 넣으면 결과가 같아야 한다.
평균 공차시간의 포함 항목과 분모는 아직 미확정이므로 현재는 대기·픽업·탑승
시간을 각각 제공한다. 예측 기반 방식과 기준 방식의 효과 비교는 아직 미구현이다.

## 검증과 남은 범위

단위 테스트는 이동·시간·상태·오류 처리, 계약 테스트는 공개 데이터·미래 호출
비노출·같은 시각 처리, 통합 테스트는 시나리오·시연 명령·3대 운행과 시간 합계를 검증한다.

제공 Unity Asset 적용, 실제 보행과 승객 취소는 후속 작업이다.
재배치와 예측·자동 배차 정책·비교 실험은 이번 Module 1 구현 범위가 아니다.
기본 3D 도형을 사용하며
과제의 제공 Asset 활용 요구까지 완료한 것은 아니다.
