# Module 1 첫 이동 시제품

## 범위와 임시 규칙

이 단계는 3×3 **블록**과 택시 3대의 도로 이동을 구현한다. 따라서
교차로는 4×4개이고, 인접 교차로 사이에 양방향 도로가 있다.
Passenger 데이터 객체를 정의하지만 호출 발생·승객 이동·배차·재배치·공차 지표는 아직 구현하지 않는다.
모듈 간 공용 계약과 공개 진입점은 기존대로 미확정이다.

다음은 Module 1 이동 시제품에만 사용하는 임시 규칙이다. 팀 공통
시간·거리·상태 계약으로 사용하지 않는다.

- 좌하단이 `(0, 0)`, 동쪽이 +x, 북쪽이 +y, 위쪽이 +z이다.
- 교차로 좌표는 정수 `(열, 행)`이며 각 축 범위는 0~3이다.
- 블록 간격과 속도는 설정 파일에 각각 m, m/s로 표시한다.
- 시뮬레이션 시간은 0부터 시작하며 고정된 tick 간격(초)으로 진행한다.
- 각 택시는 설정된 순환 경로를 일정 속도로 반복한다. 경로의 연속 지점과
  마지막→첫 지점은 반드시 도로로 연결되어야 한다.
- 난수를 사용하지 않는다. 같은 설정과 tick 수는 같은 위치를 만든다.
- 화면의 재생 속도는 tick 실행 빈도만 바꾼다. 위치 계산에는 컴퓨터의
  현재 시각이나 화면 프레임 수를 사용하지 않는다.
- 이동 상태 `demo_cruising`은 시연 전용이다. 공용 택시 상태가 아니다.
  이 단계에는 상태 전이가 없으며 일시정지는 화면의 시간 진행만 멈춘다.
- 차량 겹침, 충돌 회피, 교통 신호와 차선은 모델링하지 않는다.

설정은 `configs/module1_demo.toml`에 둔다. 잘못된 크기, 택시 수,
중복 ID, 연결되지 않은 경로와 0 이하/유한하지 않은 수치는 오류로 거부한다.
이 규칙을 바꾸거나 다른 모듈과 연결할 때 공용 계약을 먼저 합의한다.

## 검증 명령

Python 환경 설정은 [개발 시작 가이드](development_start_guide.md)를 따른다.

```bash
python -m pytest
python -m module1_simulation --headless --steps 400
```

3D 화면은 다음처럼 설치 후 실행한다. 저장소 루트에서 실행한다.

```bash
python -m pip install -e ".[dev,simulation]"
python -m module1_simulation
```

Space: 일시정지/재개, R: 초기화, 1/2/3: 0.5/1/2배속,
방향키: 카메라 회전·높이 조절, 마우스 휠: 확대/축소, Esc: 종료.
흰 배경의 화면에 시뮬레이션 경과 시간, 재생 상태·배속과 택시별 이동 상태를 표시한다.
`Moving`은 정해진 시연 경로를 이동한다는 의미이며 승객 탑승을 의미하지 않는다.
택시 좌표는 D 키로 표시하거나 숨긴다. 단위는 m이며 좌하단 원점 기준이다.
기본 설정을 바꾸려면 `--config <경로>`를 사용한다.
Panda3D가 없는 환경에서도 헤드리스 실행과 이동 로직 테스트는 가능하다.

Passenger는 ID, 출발·도착 교차로, 호출 시각(시뮬레이션 초),
초기 상태 `waiting`을 갖는 불변 데이터 객체이다. 아직 생성 스케줄과
배정·탑승·하차 전이는 없으며, 공용 호출 계약으로 사용하지 않는다.
시간은 `SimulationClock`이 관리하고 `Simulation`이 그 tick으로 위치를 계산한다.

제공 Asset은 Unity 패키지이므로 이 단계에서는 직접 만든 기본 3D 도형으로
표시한다. Asset 변환과 적용은 미구현이다. Panda3D는 이 시제품에 대해
사용자가 승인했으며 프로젝트 전체의 3D 도구 확정은 아니다.

헤드리스 실행은 지정한 tick 진행 후 최종 시각과 택시 위치를 JSON으로
표준 출력에 표시한다. 파일과 외부 서비스에 결과를 전송하지 않는다.
