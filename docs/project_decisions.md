# 프로젝트 공통 결정 기록

이 문서는 여러 모듈에 영향을 주는 미확정 사항과 확정된 주요 결정을 관리한다. 미확정 항목을 Agent가 독단적으로 프로젝트 표준으로 바꾸지 않는다.

## 1. 결정 상태

| 상태 | 의미 |
|---|---|
| 미확정 | 팀 또는 사용자의 결정이 필요함 |
| 임시 | 제한된 범위에서만 사용하는 가정이며 재검토가 필요함 |
| 확정 | 프로젝트 공통 기준으로 승인됨 |
| 폐기 | 더 이상 적용하지 않으며 대체 결정을 함께 기록함 |

## 3. 결정 원칙

- 여러 모듈에 영향을 주는 결정은 구현 전에 가능한 범위에서 합의한다.
- 임시 결정을 사용해야 하면 적용 범위와 되돌리는 비용을 기록한다.
- 결정은 선택한 대안뿐 아니라 선택 이유와 제외한 주요 대안도 남긴다.
- 결정이 바뀌면 기존 기록을 지우지 않고 상태와 대체 결정을 연결한다.
- 결정된 값은 관련 공용 문서, 코드, 설정과 테스트에 반영한다.
- 일정만을 이유로 데이터 유출, 계약 불일치 또는 재현성 문제를 허용하지 않는다.

- 검토한 대안: Module 1 재배치까지 같은 브랜치에서 구현하는 방식은 사용자 요청에 따라 제외했다. 오프라인 학습 CSV에서 타깃만 제거해 런타임에 쓰는 방식은 미래 정보 유출 위험으로 제외했다. 전체 30분 수요 최적화와 운행 중 재배치 중단은 초기 정책보다 상태·최적화 복잡도가 커 제외했다.

- 호환성 또는 전환 계획: 현재 Module 1에는 `reposition`을 전달하지 않고 현재 Module 2 데이터셋을 온라인 입력으로 재사용하지 않는다. 각 담당자가 계약을 구현하면 실제 실행 통합 테스트를 추가한다. 기준 배차와 재배치 정책을 교체해도 `module4-plan-0.1` 명령 경계는 유지하거나 버전을 올린다.
- 재검토 조건: Module 1 재배치와 Module 2 온라인 피처 구현, 동일 시나리오 비교 실험, 공차 시간 산식 합의, 실제 수요 데이터 평가 시.
- 후속 반영: PR #5에서 Module 2 온라인 피처와 합성 시뮬레이션 관측 연결을 구현했다. 위 배경과 인계 계획은 결정 당시 기준이며, 현재 Module 2 계약은 공용 계약 7절과 같은 날짜의 Module 2 결정 기록을 따른다. Module 1 재배치 실행과 전체 정책 비교 실험은 후속 작업으로 남는다.

### 2026-11-05 — Module 3 최근 추세 보정 예측기 추가

- 상태: 임시(Module 3 초기 MVP의 개선 후보)
- 결정자: 사용자(기준선 유지와 예측 개선 요청), Agent(누출 없는 최소 추세식 제안)
- 배경: 60분 평균 baseline은 안정적이지만 갑작스러운 수요 변화에 늦게 반응하며, 합성 Validation에서 개별 구역 오차가 크게 나타났다.
- 결정: 기존 `rolling-mean-12`를 비교 기준으로 유지하고 `recent-trend`를 기본 개선 모델로 추가한다. 최근 수준은 `lag_1`, 구간당 추세는 `(lag_1-lag_6)/5`, horizon h 예측은 `max(0, lag_1 + 0.5 × 추세 × h)`로 계산한다.
- 근거: Train/Validation에서 baseline MAE `1.644/1.599`보다 `0.942/0.931`로 낮았고 미래 타깃이나 새 의존성을 사용하지 않는다.
- 후속 검증: 모델 선택에 사용하지 않은 합성 Test 분할을 한 번 평가한 결과 baseline `1.635`, `recent-trend` `0.884`로 개선이 유지됐다. 실제 데이터 성능 근거로 해석하지 않는다.
- 검토한 대안: `lag_1` 지속 예측은 Validation MAE `0.944`, 3·6·12구간 가중 평균은 `1.234`, 강한 추세 외삽은 급격한 방향 전환에서 불안정할 수 있어 제외했다.
- 영향받는 모듈과 문서: Module 3 예측·평가·HTML 보고서, 공용 계약 8절, Module 4의 향후 소비 경계.
- 되돌림 또는 전환 계획: `--model rolling-mean-12`로 즉시 baseline을 재현한다. 실제 데이터 또는 학습 모델 도입 시 같은 출력 계약 안에서 비교 후 기본 모델을 재선정한다.
- 재검토 조건: 실제 데이터 평가, 여러 수요 패턴에서 성능 역전, Module 4 통합 또는 최종 평가 지표 합의 시.

### 2026-11-05 — Module 3 첫 기준 예측기와 출력 경계

- 상태: 임시(Module 3 초기 MVP와 Module 4 연동 준비에 한정)

- 배경: Module 2가 과거 60분 피처와 향후 30분 타깃을 제공하지만 Module 3 소비자와 온라인 예측 출력은 미구현이었다.
- 결정: `rolling_mean_12`를 향후 6개 5분 구간에 반복하는 무학습 기준 예측기를 구현한다. 출력은 `module3-forecast-0.1` JSON 계약을 사용한다. MAE는 구현 검증용 진단값으로 제공하고 같은 값을 자체 포함 HTML 보고서로 시각화하되 프로젝트 최종 평가 지표로 확정하지 않는다.

- 검토한 대안: `lag_1` 지속 예측은 단기 변동에 민감하고, 선형 회귀 이상 모델은 데이터·평가 기준이 정해지기 전에 복잡도와 의존성을 늘린다.
- 영향받는 모듈과 문서: Module 3, Module 2 학습 CSV 소비, 향후 Module 4, 공용 계약 8절, Module 3 문서와 테스트.
- 되돌림 또는 전환 계획: 학습 모델과 최종 지표가 합의되면 예측기 구현을 교체하되 `module3-forecast-0.1` 경계를 유지하거나 버전을 올린다.
- 재검토 조건: 실제 데이터 도입, 학습 모델 선택, Module 4 재배치 정책 구현 또는 최종 예측 평가 지표 합의 시.
