# 공통 테스트와 검증 기준

이 문서는 모든 모듈에 적용되는 테스트 구조, 변경 위험별 검증 범위와 필수 불변 조건을 정의한다.

## 1. 테스트 구조

테스트 프레임워크는 `pytest`를 사용한다.

전체 테스트의 공통 명령은 `python -m pytest`이며, 최초 환경 설정은 `development_start_guide.md`를 따른다.

```text
tests/
├── module1/
├── module2/
├── module3/
├── module4/
├── contracts/
└── integration/
```

- 모듈 테스트는 해당 모듈의 책임과 공개 동작을 검증한다.
- 계약 테스트는 모듈 간 입력과 출력의 형식·의미·단위를 검증한다.
- 통합 테스트는 전체 시뮬레이션 흐름과 모듈 연결을 검증한다.
- 공용 fixture는 책임과 적용 범위가 명확하도록 구성한다.
- 같은 시나리오를 여러 정책과 설정으로 검증할 때 parametrization을 사용한다.
- 커버리지 수치만 높이기 위한 의미 없는 테스트를 추가하지 않는다.

## 2. 변경 위험별 검증

### 국소 변경

- 변경된 함수 또는 구성요소의 테스트
- 직접 연결된 공개 인터페이스 확인

### 모듈 변경

- 해당 모듈 테스트
- 공개 입력과 출력 확인
- 인접 모듈과의 계약 테스트
- 주요 실패 경로 확인

### 공용 계약 또는 통합 변경

- 영향을 받는 모든 모듈 테스트
- 계약 테스트
- 전체 시뮬레이션 흐름 확인
- 동일 시드 재실행 결과 확인
- 기준 방식과 예측 기반 방식의 비교 실행
- 평가 지표 계산 기준 확인

실행 명령이 저장소에 정의되어 있지 않다면 추측하지 않는다. 수행하지 못한 검증과 이유를 보고한다.

## 3. 우선 검증할 불변 조건

- 한 택시가 동시에 두 명 이상의 승객을 태우지 않는다.
- 한 승객 호출이 동시에 두 대 이상의 택시에 배정되지 않는다.
- 완료된 호출은 다시 배차되지 않는다.
- 택시 위치가 정의된 가상 도시 범위를 벗어나지 않는다.
- 이동 시간과 대기 시간은 음수가 아니다.
- 시뮬레이션 시간은 역행하지 않는다.
- 택시 상태와 승객 호출 상태의 조합이 모순되지 않는다.
- 배차 명령은 존재하는 택시와 호출만 참조한다.
- 재배치 명령은 유효한 목적지를 참조한다.
- 예측 결과는 유효한 대상 시점과 구역을 참조한다.
- 평가 지표 구성요소의 합계가 전체 값과 일치한다.
- 동일한 시드와 설정은 동일한 시나리오를 생성한다.
- 의사결정 시점 이후의 실제 정보가 입력에 포함되지 않는다.

새로운 불변 조건을 발견하면 구현 내부의 암묵적 가정으로만 남기지 않고 이 문서와 테스트에 반영한다.

## 4. 결함 수정과 실패 처리

- 버그를 수정할 때는 가능한 경우 재현 테스트를 먼저 추가한다.
- 테스트를 통과시키기 위해 검증을 약화하거나 실패를 숨기지 않는다.
- 정상적으로 발생할 수 있는 빈 결과와 시스템 오류를 구분한다.
- 실패한 검증을 생략했다면 이유와 영향을 보고한다.

## 5. 정적 분석과 CI

- 정적 분석 및 자동 포맷 도구는 `project_decisions.md`에 확정된 뒤 사용한다.
- 도구가 확정되면 `pyproject.toml`, 로컬 명령과 GitHub Actions에 동일하게 반영한다.
- CI의 기본 환경은 GitHub-hosted Ubuntu runner와 Python 3.13이다.
- 렌더링과 무관한 시뮬레이션 로직은 가능한 범위에서 헤드리스로 검증한다.
- GPU나 실제 3D 환경이 필요한 검증은 일반 CI와 분리할 수 있다.
